## 3. Newman-ы үр дүн

| Ажиллуулалт | Файл | requests | assertions executed | assertions failed | exit code |
|---|---|---|---|---|---|
| PASS | `results/newman-pass.txt` | 25 | **53** | 0 | **0** |
| FAIL | `results/newman-fail.txt` | 25 | 53 | 1 | **1** |
| DOWN | `results/newman-down.txt` | 25 (бүгд ECONNREFUSED) | 53 (бүгд fail) | 53 | **1** |

**Тестийн тоо:** 11 тестийн бүлэг, 25 хүсэлт, **53 assertions** (`results/newman-pass.txt`-тэй таарна).

**FAIL:** `lab05-collection-fail.json`-д T1-ийн хүлээгдэх статусыг 201-ийн оронд зориуд 200 болгосон тул 1 assertion унаж, exit code 1 гарсан. Үндсэн `lab05-collection.json` зөв хэвээр.

**DOWN:** Сервер унтарсан үед хүсэлт серверт хүрэхгүй `ECONNREFUSED` гарна. Энэ нь интерфейсийн (холболтын) алдаа бөгөөд oracle-ийн алдаа биш: oracle нь хариуг хүлээн авсны дараа утгыг шалгадаг, харин энд хариу ирээгүй тул шалгах зүйл байхгүй.

## 4. Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудыг тодорхойлох алхам байлаа, учир нь оюутан, хичээл, урьдач гэсэн хэд хэдэн хамааралтай шинж чанарыг салгаж төлөөлөх утга болгох хэрэгтэй болсон. Боломжгүй хослол тааралдсан: "оюутан байхгүй" үед "урьдач хангана/хангахгүй" гэсэн сонголт утгагүй, учир нь үзсэн хичээлийн жагсаалт оюутан байж л оршино. Мөн "хичээл байхгүй" үед урьдач нөхцөл тодорхойгүй тул эдгээр хослолыг тусад нь тест болгоогүй. Зааварт тодорхойгүй байсан давхар алдааны дарааллыг T7, T8-аар тогтоосон: сервер эхлээд оюутны байхгүй байдал, дараа нь идэвхгүй байдал, дараа нь хичээлийн байхгүй байдал, хамгийн сүүлд урьдач нөхцөлийг шалгадаг. Эхлээд хүлээгдэх утгыг таамаглаж бичээд, дараа нь сервер дээр баталгаажуулсан. Тестүүд согог олсонгүй, сервер спецификацийн дагуу ажиллаж байна. Харин FAIL ба DOWN ажиллуулалтууд CI quality gate зарчмыг харуулсан: оракл буруу бол exit code 1, сервер унтарсан ч exit code 1 тул тэдгээрийг гаралтын текстээр ялгана.
